### 2.4 未修复的物理 bug

**问题**: `physics.py` 已经把 `P_jam_W` 当作**单 cell 功率**(per-cell),公式为:
```python
N = float(jammer.n_cells)  # 5
P_cell_dBm = 10log10(physics.P_jam_W * 1000)
P_peak_dBm = P_cell_dBm + 20log10(N)  # 主瓣相干叠加 N²
```

但 `EnvConfig` 默认值是 `P_jam_W=10.0`,语义是"总功率 = 5 cells × 2.0 W/cell"。runner 和 tests 也用 10.0。

**后果**: 新公式下 P_jam_W=10.0 意味着 10 W/cell × 5 cells = 50 W 总,加上 N² 相干增益 → JNR 比 S1 高 7 dB,物理不可比。

**修复方案**: 见 §10。

## 11. S3-S7 路线简述

### 11.1 S3 — cell binding(资源分配)

**新增动作**: `Bernoulli([2]×5)` cell binding(per-cell 独立 idle/jam)
**动作空间**: `Bernoulli(5) + Cat(3) + Cat(5)` 三头
**物理**: cell weights `w_mn ∈ {0, 1}` 替代 S2 的全 1
**研究问题**: PPO 能否学到"radar 切换 beam_az 的间隙集中更多 cell"(动态功率管理),还是"全 jam 一直发"最优?
**风险**: Bernoulli(5) 初期可能全 0(reward=0,梯度=0)。Mitigation: entropy bonus + cell head 更高 lr。

### 11.2 S4 — 2D 5×5 UPA

**新增维度**: az × el ∈ {-60,-30,0,30,60} × {-30,-15,0,15,30} 共 25 beam
**动作空间**: `Bernoulli(25) + Cat(25)`(base idle/jam 移除,语义由 cell binding 承担)
**研究问题**: PPO 能否在 2D beam 空间(625 模式)学到有效策略?
**性能风险**: 25 cell × 25 beam AF 计算 > 50ms/step。需预先 profile,必要时做 AF 查表预算。

### 11.3 S5 — 2 jammer cooperative

**首次 multi-agent**。每 jammer 独立 actor + 共享 critic(CTDE)。
**IPPO 风格**(参数共享,简单),不是 full MAPPO;S7 才升级。
**研究问题**: 2 jammer 能否学到分工(一个打 svc_0,一个打 svc_1)?
**必做**: S5 进场前必须先复现 S4 single-agent 饱和点作为对照。

### 11.4 S6 — 1 jammer vs 2 radar 学习型对手

**首次对手学习**。Radar 从 rule-based 升级为 actor。
**reward**: 默认零和(jammer reward = -detect_ratio; radar reward = +detect_ratio)
**研究问题**: 对抗训练是否产生军备竞赛,还是陷入 Nash 均衡停滞?
**风险**: 振荡或坍缩。Mitigation: PFSP(past policy sampling)+ opponent pool + 每 N iter checkpoint 做 ELO 评估。

### 11.5 S7 — 完整 two-team MAPPO

**终点**。2 jammer vs 2 radar,4 agent 全学习。
**信用分配**: counterfactual baseline(COMA-style)或 value decomposition(QMIX-style)。S7 实现时与用户讨论选型。

## 12. 已知陷阱(避免重蹈覆辙)

### 12.1 forward-evaluate clamp 毒化 ratio

(memory `twoteam_wp3_2_phaseB_redesign.md`)

如果 actor 在 sample 时和 forward-evaluate 时行为不一致(例如 sample 用了 mask 而 forward 没用),PPO ratio 会偏向 0 或 inf,11 跑全中招。

**Mitigation**: PPO update 前 microverify(1 iter 检查 ratio 直方图,确认集中在 1.0 附近)。

### 12.2 跨 harness 数字不可比

(memory `twoteam_tier21_adaptive_outcome.md`)

不同实验 harness 的 reward scaling / episode length / opponent pool 差异,会让"看起来 5σ 超越教师"被同协议对照证伪(RL ≈ BC 不可分)。

**Mitigation**: 任何 RL vs BC 比较必须在**同一 harness 同一 episode 配置**下跑。不要拿 PPO on X 的数字去比 BC on Y。

### 12.3 BC lock + PFSP collapse

(memo `twoteam_wp3_production_smoke_fail.md`)

如果 actor 用 BC warm-start 然后用 PFSP(past policy sampling)训练,容易陷入:
- BC lock: actor 永远模仿 teacher,不探索新策略
- PFSP collapse: opponent pool 全是 BC,actor 学到的只是反 BC

**Mitigation**: S2 起默认 scratch(无 BC warm-start)。如果 multi-seed 显示卡死率 > 50% 才考虑 BC。

### 12.4 POMDP 难度跳变

(plan §12 risk 1)

每 phase 加一个 POMDP 维度(如 S1 jammer 需从历史 detect 反推 radar beam_az),PPO 可能直接学不会(曲线平)。这是**研究问题本身,不是 bug**。如果某 phase PPO 不收敛,与用户讨论是否给 jammer obs 加 noisy 估计(降 POMDP 难度)。

### 12.5 多 discrete head KL 易错

(plan §12 risk 2)

MultiDiscrete([3, 5]) 的 KL 是两个 head KL 之和。PPO ratio 计算要把两个 head 的 logp 加起来。

**Microverify**: 1 iter 检查 actor forward + sample + log_prob + entropy 数值。详细看 trainer.py 的注释。

### 12.6 entropy anneal 杀高熵 search

(memo `twoteam_wp3_1_beam_sweep_collapse.md`)

如果 entropy_coef anneal 太快(0.01 → 0.001 in 100 iter),actor 会过早 collapse 到 deterministic policy,失去 search 能力。S1 Amend02 用 `anneal_frac=0.5`(即 500 iter 才 anneal 完)。

**S2 默认**: 沿用 Amend02 配置(anneal_frac=0.5, target_kl=0.02, entropy_coef_init=5e-3)。

### 12.7 manifest seed collision

(plan §12 risk 7)

新 `2101xxxx` seed 块(S1-S4 共用)必须 verify 与 lite 的 `2100xxxx` 块零重叠。Manifest 生成后检查 `MANIFEST_AUDIT.json` 的 `verdict: CLEAN`。

## 16. 紧急情况

### 16.1 测试突然 FAIL(回归)

- 先 `git log --oneline` 看最近 commit
- 跑 `git stash` + `git checkout <last-good-commit>` 验证是否回归
- 如果回归 = 你刚才改的 bug;如果原始就 FAIL = lite 或 S1 测试有 flake

### 16.2 PPO loss NaN

- 学习率太高?S2 默认 `actor_lr=3e-5, critic_lr=1e-3`
- Observations 归一化?检查 obs builder 是否有异常 scale
- 物理输出 NaN?跑 unit test 看 AF / JNR 数值

### 16.3 GPU OOM

- n_envs=16 × horizon=64 应该 < 4GB。如果 OOM,可能有内存泄漏(reward tensor 没 detach)
- `nvidia-smi` 看进程
- 临时降 n_envs 到 8

### 16.4 push 被拒

- "Permission denied (publickey)": SSH key 没注册,看 §5.1
- "could not read Username": 用了 https URL,改用 `git push git@github.com:ExuberantWitness/FluxPhased-.git <branch>`
- "fetch first": 远程有新 commit,先 `git fetch` + `git rebase`(不要 merge,保持线性)

### 16.5 联系不到用户

继续做 §10 修复 + §15 checklist 的 1-7 步(都是 local 操作,不需要授权)。第 8 步(PPO 训练)耗 GPU 资源,**等用户确认再启动**。

## 17. 故障排查 FAQ

按症状查表,大部分问题都在这里:

### Q1: `pytest: command not found` 或 `No module named pytest`

**症状**: 跑测试报错找不到 pytest
**根因**: conda env 没激活,或激活错了 env
**修复**:
```bash
source /home/ubuntu/miniconda3/etc/profile.d/conda.sh
conda activate fluxphased
which pytest  # 应输出 /home/ubuntu/miniconda3/envs/fluxphased/bin/pytest
```

### Q2: `ImportError: No module named 'env'` 跑测试时

**症状**: `from env.gpu.array_face_s1 import ...` 报错
**根因**: PYTHONPATH 没设
**修复**:
```bash
cd /home/ubuntu/CODE/g3-bsta-fastwork
PYTHONPATH=$PWD pytest -q tests/array_face/test_array_factor_s1.py
# 或 export 一次,后续 shell 都用
export PYTHONPATH=/home/ubuntu/CODE/g3-bsta-fastwork
```

### Q3: S2 测试 `test_jnr_s2_*` 报 JNR 值超预期

**症状**: `assert 10.0 < jnr_broadside.item() < 15.0` 失败
**根因**: S2 物理 bug 未修复(P_jam_W 还是 10.0,旧总功率语义)
**修复**: 按本文档 §10.2 走 5 步修复方案 A

### Q4: PPO 训练 loss 在前 50 iter 变 NaN

**症状**: `train_metrics.jsonl` 里 loss 字段变 NaN
**根因**:
  - (a) observations scale 异常(检查 obs builder 是否归一化)
  - (b) 物理 JNR 太高(> 80 dB,导致 sigmoid 饱和到 0/1)
  - (c) actor logits 爆炸(learning rate 太高)
**修复 顺序**:
```bash
# 1. 验证物理合理(应输出 10-15 dB)
python -c "
import torch
from env.gpu.g3_bsta_lite.physics import default_debug_physics_config
from env.gpu.array_face_s2 import RadarULAConfig, JammerULAConfig, compute_jnr_db_s2
physics = default_debug_physics_config(P_jam_W=2.0)
jnr = compute_jnr_db_s2(physics, RadarULAConfig(), JammerULAConfig(),
    jammer_active=torch.ones(1, dtype=torch.bool),
    jammer_service_id=torch.zeros(1, dtype=torch.int64),
    victim_service_id=torch.zeros(1, dtype=torch.int64),
    radar_beam_az_idx=torch.tensor([2]), jammer_beam_az_idx=torch.tensor([2]))
print(f'JNR main: {jnr.item():.2f} dB')"
# 2. 若 JNR 正常,降 actor_lr 到 1e-5 重试
```

### Q5: actor entropy 在 iter 50 内降到 < 0.1

**症状**: entropy坍缩,policy 变 deterministic,学习停滞
**根因**: entropy_coef 太低 或 anneal_frac 太小
**修复**: 用 Amend02 配置(`entropy_coef_init=5e-3, entropy_anneal_frac=0.5, target_kl=0.02`),这是 S1 验证过的最佳。S2 沿用。

### Q6: `git push` 报 `Permission denied (publickey)`

**根因**: SSH key 未注册到 GitHub 账号
**修复**:
```bash

# 2. 复制整行(以 ssh-ed25519 开头)
# 3. 浏览器打开 https://github.com/settings/ssh/new
# 4. Title 随便,Key 粘贴,保存
# 5. 验证
ssh -T git@github.com  # 期望 "Hi ExuberantWitness!"
```

### Q7: `git push` 报 `could not read Username`

**根因**: 用了 https URL(默认 remote),git 试图交互式询问用户名

## 18. 术语表(Glossary)

| 术语 | 全称 / 含义 |
|---|---|
| **array-face** | "阵面" 路线,把单天线 jammer/radar 升级为相控阵,引入 array factor 物理 |
| **lite** | G3-BSTA-lite,scalar 链路预算的简化版 toy(s1-s7 的 base) |
| **S1-S7** | 7 个 phase:S1 radar ULA, S2 jammer ULA, S3 cell binding, S4 2D UPA, S5-7 multi-agent |
| **ULA** | Uniform Linear Array(均匀线阵) |
| **UPA** | Uniform Planar Array(均匀面阵,2D) |
| **AF** | Array Factor(阵面方向图系数),决定主瓣/旁瓣增益 |
| **Rx AF / Tx AF** | 接收端 AF / 发射端 AF(radar Rx, jammer Tx) |
| **JNR** | Jammer-to-Noise Ratio(干噪比),dB |
| **P_detect** | 检测概率,radar 在干扰下能 detect target 的概率 |
| **macro_drop** | Macro Drop Ratio,mission-level 失败率(主要 KPI) |
| **witness** | BC teacher 的 macro_drop(lite R2 = 0.2680),PPO 想打破的 reference |
| **broke out / stuck** | PPO 曲线两种结局:broke out = final > 0.12,stuck = final ≈ 0.09(random baseline) |
| **PPO** | Proximal Policy Optimization(on-policy RL) |
| **MAPPO / IPPO** | Multi-agent PPO / Independent PPO(multi-agent 变体) |
| **BC** | Behavior Cloning(imitation learning,从 teacher 学) |
| **POMDP** | Partially Observable MDP(部分可观 MDP) |
| **CTDE** | Centralized Training Decentralized Execution(multi-agent 训练范式) |
| **GAE** | Generalized Advantage Estimation(PPO 标准 advantage 算法) |
| **witness ref** | 0.2680 = lite BC teacher 的 macro_drop(不能打破这个就是 BLOCKED) |
| **R2 Gate-3** | lite learning-repair 的最终 gate,PPO 没过 → BLOCKED(已记入 FINAL_VERDICT) |
| **Amend02** | S1 探索增强配置:entropy_coef=5e-3, anneal_frac=0.5, target_kl=0.02 |
| **Amend01 / Amend03** | Amend02 的前/后探索(都被否决) |
| **manifest** | 场景种子清单(2101xxxx 块,S1-S4 共用) |
| **MDP_SANITY** | Profile 名,fully observable MDP(对比 POMDP) |
| **FORENSIC** | 取证模式(分析 lite R2 BLOCKED 时用) |
| **handoff/evidence** | protected branch(永远不动) |
| **PRO6000** | RTX PRO 6000 GPU(Blackwell sm_120),需要 PyTorch ≥ 2.11 |
| **signal-light** | 信号灯,GREEN/YELLOW/RED 三级复现判定(见 §10.7) |
| **M0/M1** | 测试层级:M0 = 物理单测(array factor),M1 = env contract(action/obs/ledger) |
| **no-godview** | env 设计原则:agent 不能看到 hidden state(只能从历史 obs 推断) |
| **ledger identity** | 每个 mission 最终状态(success / timeout / dropped)的恒等式 |
| **potential shaping** | reward shaping 技巧:`r + γΦ' - Φ`,保证 telescoping 不偏置最优策略 |
