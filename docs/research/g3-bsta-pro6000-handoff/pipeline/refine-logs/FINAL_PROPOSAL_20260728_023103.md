# Final Proposal：FluxPhased MFR-IQ Budgeted Target Allocation

## 1. Proposal Status

**状态**：研究与实现提案；未实施、未训练、未宣称任何 gate PASS。  
**核心方法**：物理绑定的 per-emitter 硬能量/峰值功率/波束约束下的 target–time allocation；只有平台证明资源可池化时才使用 shared-team 约束，并配合 IQ 校准的 task-specific detector/information progress。  
**强制入口**：先恢复 provenance、纠正原 gate，并用 oracle/headroom 证明新环境有可达余量。  
**新 gate ID**：`G3-BSTA`（Budgeted Service-Target Allocation）；在 preregistration 时冻结其 protocol hash。  
**原结果处理**：原 G2'a 保持 FAIL；新 benchmark 是新环境、新评估协议，未来结果不得回写成原 gate PASS。

**当前实施状态**：`BLOCKED`。所有可见 refs（截至审查时 `origin/twoteam/bc-ppo=983e1e5`）仍没有 MFR/M7 source。进入实现前必须提供 `SOURCE_HANDOFF.json`，包含 `repo_path/repo_url`、exact commit、source archive/URI、SHA-256、owner 和交接时间；否则 PRO6000 只能完成 P0。

## 2. Why This Is the Narrowest Defensible Change

当前问题不是 PPO 网络容量，而是：

1. `noise` 脚本可无代价 always-on；
2. 每个 jammer 独立 on/off，缺少 target/channel/resource allocation；
3. `max(0.1, 1/sqrt(1+JNR))` 使约 20 dB 后的 transition 完全饱和；
4. sampled Bernoulli、untrained random 与真正 state-dependent policy 在 `drop_ratio` 上不可辨；
5. gate 误用了 blink comparator、`H0: delta=0` 和单 training seed。

推荐机制只增加支撑非平凡决策所需的最少元素：

- 有平台依据的 per-emitter power/energy resource；只有能证明资源可转移时才允许 team pooling；
- 有平台依据的 simultaneous-beam cap；`K=1` 是待验证的首版假设，不是为了制造 headroom 的自由旋钮；
- 每步选 idle 或一个 `(emitter, physically-addressable service)`；
- 固定校准功率，不加入连续功率控制；
- 通过统一 detector/information path 影响所选 target；
- 同一 action template、mask 和 physics path 对所有策略生效。

## 3. Formal Decision Process

### 3.1 State and Resource State

环境隐藏状态记为 `x_t`；jammer 的可用因果历史为 `h_t^J`。对 emitter `j` 的资源状态：

\[
E_{j,t+1}=E_{j,t}-\Delta t P_{j,\mathrm{exec},t},
\qquad E_{j,t}\ge0,\qquad
0\le P_{j,\mathrm{exec},t}\le P_{j,\max}.
\]

只有 M7 source/platform binding 证明存在共享电源或协同 team cap 时，才可把上式聚合成 team resource。首版候选 `K_total=1` 必须有 RF chain/mission 依据；否则使用真实 per-emitter `K_j`，或返回 `BLOCK_RESOURCE_BINDING`。episode 不充电；如真实平台要求 recharge，另开未来版本，不能在本 gate 中后验加入。

若固定功率为 `P_fixed`、可发射时长为 `T_active,max`，要排除全程开启至少要求

\[
E_{j,0}<P_{\mathrm{fixed},j}T_{\mathrm{active,max}},
\]

而不是与 team peak power 比较。该约束仍必须来自平台/预注册 mission scenario，不能只为打破 always-on 而设。

### 3.2 Action

对 emitter `j=1,\ldots,J` 和固定 addressable-service slots `i=1,\ldots,N_max`：

\[
a_t\in\{0\}\cup\{(j,i)\}.
\]

其中 0 表示 idle，`(j,i)` 表示 emitter `j` 以固定校准功率干扰物理上可寻址的 service `i`。若系统经 P0 证明只有一个等效 transmitter，才可退化成 `idle-or-target`。只有当前因果可见、发射机可达、energy 足够的动作合法；`idle` 永远合法。

`service i` 不能只是 simulator 内部 task ID。它必须对应可验证的选择性机制之一：不同 radar receiver/beam direction、range/Doppler/angle gate、frequency/channel、或被截获且可时间对准的 radar dwell。若现有 off-board noise jammer 是单接收机上的无选择宽带噪声，而不存在上述 gate，则 target-local action 物理上无定义，返回 `BLOCK_TARGET_LOCALITY`，不能直接给内部 task 注入 JNR。

使用固定维度 masked categorical，而不是 J 个独立 Bernoulli：

- 避免同一 joint allocation 被多个 Bernoulli 组合重复表达；
- mask 明确表达资源与 target 可行性；
- sampled policy 和 argmax policy 语义清楚；
- log-probability 可以在 PPO rollout/update 中一致复现。

### 3.3 In-Band Interference and SINR

对 receiver/service candidate `i`，由 emitter/service cross-talk matrix 明确选择性：

\[
J_{i,t}
=\sum_j z_{j,t}P_{j,\mathrm{jam}}
G_{j\rightarrow i,t}\rho_{j,i,t}L^{-1}_{j,i,t}
\chi_{j\rightarrow i,t},
\]

\[
\mathrm{SINR}_{i,t}
=\frac{S_{i,t}}
{N_{i,t}+J_{i,t}+C_{i,t}}.
\]

实际代码必须在线性功率域计算。`G`、`rho`、`L`、选择性 gate 与 cross-talk `chi` 的定义、单位和校准必须进入 `SYMBOL_MAP.md`。如果 current physics 无法产生 service selectivity，不能把缺失项置成方便的 0/1 常量；该候选应停止。

### 3.4 Task-Specific Progress

主模型禁止统一的 floored `sigma-progress`。

#### Detect task

由固定 `P_fa` 下的 detector 计算：

\[
P_{d,i,t}
=Q_N\left(\sqrt{2\gamma_{i,t}},
\sqrt{\eta(P_{fa},N)}\right),
\]

或使用与 held-out IQ Monte Carlo 匹配的 lookup table。P0 后必须由实际 task semantics **冻结唯一 transition**：累计非中心参数、expected service 或显式 detection draw 三者不能留给 executor 根据 headroom 临场选择。

#### Track/estimate task

若 source 明确 task 是动态 track/estimate，则使用完整预测—检测—量测更新。量测信息项可写为：

\[
\Delta\mathcal J_{i,t}
=H_{i,t}^{\top}R^{-1}_{i,t}H_{i,t}.
\]

但还必须实现/复用 `P^- = FPF^T+Q`、missed detection、data association 假设、状态坐标变换，以及 covariance/information 到 task completion 的预注册映射。若这些语义不存在，不能用 CRB 代替完整 tracker；返回 `BLOCK_PHYSICS_SEMANTICS`。

#### Legacy mode

`legacy_sqrt` 仅用于 regression/ablation；主结果 config 必须使用经校准的新模式。数值 `eps` 只能防止除零，不能造成可见物理 floor。

## 4. Observation Contract

Actor 可使用：

- `remaining_energy / initial_energy`；
- `time_remaining / episode_horizon`；
- 每个 candidate 的 visibility/feasibility；
- 延迟、带噪的 emission/carrier/bearing/gain proxy；
- intercept confidence 与 age；
- 由 ESM/历史推断的 task urgency proxy；
- previous executed action。

Actor 不可使用：

- 真值 queue length、exact internal progress 或 exact deadline，除非能证明 jammer 可截获；
- 当前尚未观测的 radar hop；
- 未来 task arrivals；
- post-action detector outcome；
- rule radar next action；
- env RNG state。

每个 observation field 必须记录名称、slice、shape、range、unit、causal source 和 latency。改变隐藏 queue/future state 而保持 observable history 不变时，jammer observation 必须逐元素相同。

action mask 也属于信息通道：每个 mask bit 必须是 actor-visible observation/history 的确定函数，不能从真值 `alive`、hidden geometry 或内部 task state额外生成。candidate association 必须定义 false alarm、miss、latency、slot birth/death 与 ID reuse；否则 stable slot 本身会泄漏真值。

如果 action 需要历史而当前 observation 不是充分统计量，actor 与 causal planner 都必须使用相同的 recurrent state/belief update；同时规定 hidden-state reset、truncation、sequence minibatch 与 burn-in。不能让 planner 查看完整 env state、却让 MLP actor只看单帧。

## 5. Reward and Metrics

### Primary scientific metric

继续使用 raw:

\[
\mathrm{drop\_ratio}
=\frac{\text{dropped tasks}}
{\text{eligible task arrivals}}.
\]

必须冻结 numerator、denominator、`eligible_arrivals=0` 的 NA 处理、episode reset、unfinished-at-horizon、termination/truncation 和 aggregation order。场景 arrival 数不同时，先明确 estimand 是 episode-macro mean 还是 pooled micro ratio，二者不能混用。

### Training reward

在 P0/P2 task semantics 获批后，**预先固定一种** training reward，并证明其对应的 episode return 与主 estimand 的关系；不能把 newly-dropped count、terminal ratio、expected service 或 detector draw 留作实现时的可选分支。若选择 terminal raw metric，任何 shaping 只允许 potential-based：

\[
r'_t=r_t+\gamma\Phi(s_{t+1})-\Phi(s_t),
\]

并在 terminal 令 potential 正确归零。energy 是硬约束，不再加 learner-only active penalty。

### Secondary metrics

- `drop_per_kJ`（energy=0 时记 NA，不定义为 0 或无穷）；
- target switching 与 allocation entropy；
- energy used/remaining；
- constraint violations；
- requested/executed action mismatch；
- return/drop correlation；
- `P_d`、SINR 和 drop-cause distributions。

Secondary metrics 不替代 `G3-BSTA` 的 raw-drop superiority。

## 6. Fair Comparator Family

全部使用同一 observation 和 action feasibility path：

1. `always_off`；
2. `random_feasible`；
3. `budgeted_barrage` / maximum-feasible fixed schedule；
4. `budgeted_round_robin`；
5. `periodic_blink`，完整预注册 duty/phase family；
6. `edf_or_threat_first`；
7. `reactive_target_follower`；
8. `marginal_information_per_joule`；
9. `assignment_index`，必要时 Hungarian/knapsack；
10. `untrained_actor`；
11. `trained_shuffled_observation`。

每个脚本 family 的完整超参网格、scenario-macro selection score 和 deterministic tie-break 必须预注册；calibration 后每族保留一个 frozen finalist 并生成 `BASELINE_FREEZE.json`。确认性 gate 对**全部 frozen finalists**检验，而不是只检验可能选错的 calibration winner。locked test 上不得继续调 learner 或 comparator。

## 7. Oracle-First Reachability

### Current environment

先在原 on/off action 上做 reduced exact enumeration/DP 与 admissible bound：

- 对每个场景 `s`，令 `U_s` 为 exact/admissible pathwise upper bound、`B_{b*,s}` 为独立 calibration 冻结脚本，`g_s=U_s-B_{b*,s}`；只有 `UCB95(E[g_s])<.05` 才记 `STOP_CURRENT_G2A_INFEASIBLE`；
- bound 不紧则记 `INCONCLUSIVE`；
- 不能仅凭五个测试策略声称 universal structural impossibility。

### `G3-BSTA` environment

1. planner-development split 上建立 reduced exact DP：2–3 addressable services、经绑定的 beam cap、离散 energy、短 horizon；
2. full causal planner witness：beam search/MCTS/receding horizon；
3. clairvoyant planner 只作 optimistic ceiling；
4. planner/config/operating point 完全冻结后，转到未触碰的 headroom-confirmation split；
5. headroom 的有效证据必须是 same-observation causal witness；其 belief/history update 与 actor 相同。

Pre-PPO headroom gate：

\[
\min_{b\in\mathcal B}
\operatorname{LCB}_{95}\left(
D_{\text{causal witness}}-D_{\text{frozen finalist }b}
\right)>0.075.
\]

同时，在相邻预注册 energy settings 和 detector calibration uncertainty 两端：

\[
\operatorname{LCB}_{95}(\Delta)>0.05.
\]

energy × detector-envelope × scenario-shift 的有限 sensitivity cells 必须在 confirmation 前预注册；baseline/planner 不在 cell 内重调。只在一个甜点配置通过，视为 manufactured headroom。`.02/.03/.075/32` 等阈值是项目工程预算，不是文献常数，必须在 preregistration 中给出 error-budget/sensitivity 理由。

## 8. Learnability Controls

在 full multi-seed 训练前，pilot 必须证明：

- trained actor 相对 frozen-init 与 `random_feasible` 有一致正差；
- 对 candidate features/history 做与 slot/mask/action semantics 同步的预注册置换；简单 OOD shuffle 只作辅助，不能单独证明因果使用；
- 策略的 target choice 随 causal state 改变，而非固定 action 或 duty；
- action/state dependence 超出用相同 marginal action frequencies 生成的 permutation null；
- reward 与 raw drop 至少方向一致。

若 trained、untrained、random 或 shuffled observation 不可区分，结论是“尚未证明学习”，不是“sampled policy 达到 optimum”。

## 9. Final `G3-BSTA` Statistical Gate

### Data hierarchy

- 独立 training seeds 是最高层独立单位；
- locked environment/scenario seeds 对 learned 与 script 配对；
- stochastic policy action RNG 单独记录；
- detector RNG 与 environment RNG 单独记录；
- 至少 8 个独立 training seeds；两个短 pilot seeds 只做功能性 go/no-go，不能估 final-budget 方差。正式 N 使用外部数据或至少 6–8 个 full-config/full-budget variance pilots 的保守方差上界，并预注册备择均值 `mu_alt > .05`、power、`N_max`。

对每个 training seed `i` 与 frozen script finalist `b`：

\[
d_{i,b}=\overline D_{\mathrm{learned},i}
-\overline D_{\mathrm{frozen\ finalist}\ b}.
\]

检验：

\[
H_{0,b}:\mathbb E[d_{i,b}]\le0.05,\qquad
H_{1,b}:\mathbb E[d_{i,b}]>0.05.
\]

PASS 条件是所有 `b` 的 training-seed-level 一侧 95% lower confidence bound 都严格大于 0.05；这是 intersection–union gate。`p<0.05` 对 `delta=0` 不能替代 margin test。主 t inference 的 claim 条件于固定 locked scenario suite；若要推广至 scenario generator，另报 train-seed × scenario crossed random-effects/two-way-cluster sensitivity，并传播 stochastic baseline rollout uncertainty。

每个 train seed 必须跑完整 `scenario × action-replicate × episode` 网格。exogenous randomness 用无状态 event key `(scenario, episode, time, entity, event_type)` 在策略间对齐；action RNG 独立。scenario/action/episode 都是重复测量，不增加最终 training-seed t-test 的自由度。小 `N=8` 时不以 percentile/BCa bootstrap 代替主 t-LCB。

部署若允许 stochastic policy，必须在训练前写入 `EVAL_PROTOCOL.md`，指定 sampled 为 primary、argmax 为 secondary；不允许看过结果后切换。若部署要求 deterministic，则反过来预注册。

## 10. Falsifiable Claims

只有全部 gate 通过后，最多声称：

> 在预注册、物理绑定的 budgeted addressable-service MFR-IQ 新 benchmark、rule-radar opponent、因果 observation 和固定资源约束下，PPO jammer 在 N 个独立 training seeds 上相对每个冻结 competent scripted finalist 的 raw drop_ratio 提高超过 5pp；该结论条件于 locked scenario suite。

不能声称：

- PPO 普遍优于 scripted jammers；
- resource allocation 或 PPO 算法本身新颖；
- full planner 是 exact upper bound；
- 原 G2'a 被修复为 PASS；
- simulation-only 结果代表真实系统。

## 11. Expected Outcome and Decision Logic

- 若 provenance 无法恢复：停止；
- 若 emitter、resource pooling、beam cap 或 service selectivity 无法物理绑定：停止；
- 若 detector/IQ calibration 失败：停止；
- 若 target action 不产生局部物理效应：停止；
- 若 exact reduced policy 不依赖 causal state：停止；
- 若 competent script 接近 causal planner：接受“无 5pp headroom”，停止；
- 若 headroom 存在但 PPO pilot 不使用 observation：停止或换算法，但不得调弱脚本；
- 只有 headroom 与 learnability 都成立，才运行完整多 seed 训练。

该提案优化的是实验问题的可判定性，不保证正结果。
