# Idea Report：FluxPhased G2'a 环境重构候选

**生成方式**：三个相互独立的只读候选线程，分别从结构完整性、最小工程改动、检测物理角度生成；本报告只去重和合并，不在本阶段排序。  
**共同约束**：保留 rule radar 与 raw `drop_ratio`；所有策略使用相同因果 observation 和硬可行域；任何方案都必须先通过 oracle/headroom gate，再启动 PPO。

## 候选 A：Budgeted Sparse Beam–Target Allocation（硬预算稀疏波束/目标分配）

### 核心机制

把 off-board jammer 建模为受平台约束的 emitter 集合。每步选择少量 `(emitter, physically-addressable service)` 分配；只有平台证明能量/功率可以转移时才允许把 emitter 聚合为 team resource：

\[
\sum_b P_{b,t}\le P_{\mathrm{team,max}},\qquad
\sum_b\mathbf 1[P_{b,t}>0]\le K,\qquad
E_{t+1}=E_t-\Delta t\sum_bP_{b,t},\quad E_t\ge0.
\]

`always-on/all-target` 不再是合法动作或会耗尽未来能量。JNR 只作用于被选中的目标/频带，并通过统一的 post-processing SINR 进入 detector/information progress。

### 最小可实施形态

- `K=1` 仅在 RF-chain/mission binding 支持时采用，否则使用真实 per-emitter beam cap；
- 固定候选 target slots；
- 首版仅用 `idle` 或固定校准功率，不加入连续/多档功率；
- 若当前两 carrier 已有真实语义，则 target 与 channel 联合；否则先只做 target；
- 小动作集枚举合法 allocation templates，PPO 使用单一 masked `Categorical`；
- 全部 scripted 与 oracle 也只能输出同一 template ID。

### 物理前提

- jammer 具有有限峰值功率、episode 能量和同时成束能力；
- 路径损耗、天线增益、频谱重叠与 receiver-band noise 有明确单位；
- 预算来自平台量级、任务设定或预注册 scenario grid，不从 test seeds 反推；
- detect/track progress 由 IQ 校准后的 detector 或信息模型给出。
- **Emitter identity**：每个 action template 必须解析到实际 jammer emitter、波束/孔径、发射波形和功率口径（transmitter power 或 EIRP）；同一物理发射不能被重复记为多个可独立分配的逻辑 beam。
- **Receiver identity**：每个 candidate slot 必须解析到可区分的 victim receiver/radar channel 及其接收滤波、noise bandwidth、处理增益和 detector/task；`J` 的参考面必须明确是 receiver input、post-filter 还是 post-processing。
- **Target selectivity**：只有在 emitter 能通过角度、频率、波形或时隙对该 receiver/task 产生可校准的局部效应时，`select target i` 才是物理动作；“雷达所跟踪的目标”“雷达节点”“内部 task slot”不得在没有信号路径的情况下互换。
- **Cross-talk**：target-local JNR 不是默认对角假设。必须定义并校准 emitter-to-receiver coupling matrix，覆盖主瓣、旁瓣、频谱泄漏、共享前端和同站多 task 耦合；非 selected slot 的干扰只能在该矩阵允许时变化。
- 若 emitter/receiver 映射不唯一、selectivity 不足，或 cross-talk 使所有 target actions 产生近同一 executed interference pattern，则候选 A 退化，不能靠逻辑 target ID 制造 allocation headroom。

### 因果 observation

- remaining energy、可用 beam、时间；
- 延迟/带噪的 radar emission、carrier、bearing、任务阶段 proxy；
- 历史 action 与 intercept confidence；
- 不允许未来到达、真实内部 queue/progress、当前尚未截获的 hop 或 post-action outcome。

### 最强公平 baseline

- budgeted barrage/uniform；
- budgeted periodic blink；
- earliest-deadline/threat-first；
- reactive carrier/beam follower；
- marginal-drop-per-joule index + Hungarian/knapsack assignment；
- 在 calibration seeds 上冻结 family 和参数。

### oracle/headroom

- reduced：2–3 targets、1–2 jammers、短 horizon、离散 energy，exact DP/B&B；
- full：receding-horizon enumeration、beam search 或 MCTS；
- same-observation causal planner 用于 headroom；clairvoyant planner 单独标记为 optimistic upper bound；
- causal planner 相对冻结脚本的 paired one-sided LCB 未超过 7.5pp，则不训练。

### 决定性低成本测试

不训练 PPO。构造一个 target urgency 发生交叉的短场景，验证 exact policy 必须切换目标/功率；同时扫预注册的 energy/beam settings，检查能量守恒、动作公平和 planner-baseline headroom。

### 主要风险

- 预算太松恢复 always-on，太紧退化为 all-off；
- competent index baseline 可能接近 oracle；
- target progress 可能是 privileged information；
- 动作 projector 可能把不同请求压成同一 executed action；
- 若真实平台可持续宽带覆盖所有目标，则该约束需要重新论证。

### 工作量

在恢复实际 M7 source、完成 symbol map 并确认 emitter/receiver/selectivity/cross-talk 路径之前不估计工程日数；P0 后按真实 edit points、IQ calibration 和 reduced solver 规模重新估算。通过 headroom 后才计训练成本。

## 候选 B：Budgeted Information-Rate Blink（保留二元动作的最小修复）

### 核心机制

保持 J 维 on/off 动作，但给团队一个硬 episode energy bucket，并把现有 floored `sigma-progress` 替换为经校准的信息增量：

\[
E_{t+1}=E_t-\Delta t\sum_j a_{j,t}P_j,\qquad
\Delta I_t \approx \frac{\Delta I_0}{1+\mathrm{JNR}_t}.
\]

该候选只创造跨时间的能量分配问题，不加入显式 target/channel allocation。

### 最小代码改动

- observation 增加 remaining-energy fraction；
- 保持 Bernoulli actor shape，但 rollout/action decoder 必须 mask 能量不足动作；
- requested 与 executed action 分开记录；
- 新增 budget-aware greedy 与短 horizon exhaustive enumerator。

### 最强公平 baseline

- 完整 fixed-duty sweep；
- budgeted uniform spread；
- one-step marginal information reduction per joule；
- projected always-on 只作诊断，不自动作为唯一 comparator。

### 决定性低成本测试

在两目标、短 horizon、三档能量预算上精确枚举。若 oracle 从不改变发射时机，或无法相对最强 budget-aware script 留出 headroom，则该最小方案不足，升级候选 A。

### 主要风险

- task 同质时，timing 不重要；
- 不选 target/channel，状态依赖空间仍可能太弱；
- 硬预算取值若无平台依据，容易成为人为调节旋钮。

### 工作量

约 1–2 个工程日；是低成本证伪候选，不是默认最终方案。

## 候选 C：Delayed Spectrum–Target Assignment（延迟频谱与目标联合分配）

### 核心机制

雷达在 `B` 个频率 bins 中运行；jammer 瞬时只能覆盖 `L < B` 个 bins，且固定总功率在更宽带宽上会稀释 PSD。jammer 使用延迟、带噪的 intercept history 预测下一信道，并把有限频谱/波束资源分给 target。

\[
N_{J,j,f}=\frac{P_{j}w_{j,f}}{B_f},\quad
\sum_f w_{j,f}\le1,\qquad
J_i=\sum_{j,f}G_{ji}N_{J,j,f}B_{\mathrm{overlap}}(i,f).
\]

### 最小可实施形态

- 3–5 个 bins；
- template library：idle、各 bin spot、两 bin split、equal barrage；
- 当前 simultaneous carrier 不进入 observation，只给一 slot 延迟 intercept；
- retune latency 固定为配置；
- 用 masked categorical 选择 template。

### 最强公平 baseline

- last-seen follower；
- sweep；
- Bayesian/HMM next-channel predictor；
- urgency-weighted target/channel matching；
- same-latency randomized scan。

### oracle/headroom

小规模 belief-state DP；hindsight trace best response 只作上界，不作为可部署 headroom。

### 决定性低成本测试

对 deterministic cycle、sticky Markov、iid 三种预注册 hop traces 做 exact belief DP。可预测 trace 中应出现因果策略价值，iid trace 中不应凭空出现；spot/barrage 必须通过 IQ filter-overlap/Parseval calibration。

### 主要风险

- 若当前 radar 没有可信 frequency state，这是新子系统而非小修；
- 简单 Bayesian script 可能吃掉全部余量；
- current carrier 泄漏会把 POMDP 变成 trivial reaction；
- 会扩大到 waveform-level EW 范围。

### 工作量

约 5–8 个工程日。

## 候选 D：Emission Exposure / Track-Continuity Timing（暴露、反制或热状态的时序决策）

### 核心机制

持续发射会积累 exposure/thermal load，并导致定位、nulling、frequency escape、cooldown 或 jammer suppression；同时用 detector miss streak 或 covariance gate 表达 track continuity。这样即使只有一个 target/channel，也可能存在“何时 burst、何时静默”的长程决策。

\[
x_{t+1}=\rho x_t+\kappa P_t\Delta t,\qquad
H_{t+1}=e^{-\Delta t/\tau}H_t+
(1-e^{-\Delta t/\tau})P_{\mathrm{diss},t}.
\]

物理 transition 必须改变实际 JNR/可用性，不能只给 learner 一个 reward tax。

### 最强公平 baseline

- complete duty-cycle family；
- exposure-threshold burst；
- cool-then-burst；
- track-closest-to-loss；
- hazard-aware finite-state MPC。

### oracle/headroom

离散 exposure/thermal/miss-streak DP；same-observation causal oracle 与 full-state upper bound 分开。

### 决定性低成本测试

枚举短 horizon on/off/power sequences，检查最优策略是否出现稳定、可解释的切换，并对 `tau`、countermeasure latency、miss threshold 和 detector-fit uncertainty 做敏感性分析。

### 主要风险

- home-on-jam 对 off-board jammer 未必适用；
- 未校准 exposure/thermal 参数容易成为人为“RL tax”；
- hard miss threshold 可能制造新的饱和；
- 会改变双方闭环与 drop cause，范围最大。

### 工作量

约 5–8 个工程日，若需要 IQ 定位/反制校准则更高。

## 候选 E：Oracle-First Reachability / Stop-RL Fallback（不制造 headroom）

### 核心机制

不先改 trainer 或调超参。恢复并冻结当前环境，纠正 comparator 与统计检验，建立 deterministic replay、现有 on/off action enumerator、causal planner 和 admissible bound：

- 若 current-action upper bound 仍不能超过 frozen best scripted 5pp，正式停止当前 G2'a；
- 若 current causal lower bound 有充分余量，再用 oracle traces 定位策略失败；
- 若只有在候选 A–D 的物理重构后才有余量，明确这是新环境、新 gate，不能把结果回写成原 gate PASS。

### 最小代码改动

- 仓库内版本化 recorder/replayer/oracle/gate scripts；
- 精确定义 `drop_ratio` numerator、denominator、reset 与 aggregation；
- family selection 使用 calibration split，locked test 只评估；
- 正确检验 `H0: delta <= 0.05`；
- 至少 8 个独立 training seeds。

### 最强公平 baseline

现有 noise/reactive/blink，加 complete fixed-duty sweep、iid Bernoulli、untrained actor 和 one-step greedy。

### 决定性低成本测试

对 `J` 很小、20–50 steps 的 replay state 做完整序列枚举或 tight DP。若上界不足，立即输出 `STOP_CURRENT_G2A_INFEASIBLE`，不再运行 PPO。

### 主要风险

- 可能只产出诚实负结果而没有 learned-jammer 方法；
- reduced bound 可能不够紧；
- 对当前冻结环境的不可达性不代表一般 RL jammer 无效。

### 工作量

0.5–3 个工程日，且应作为所有其他候选的 Phase 0。

## 所有候选共享的 progress 物理选项

候选不是通过选择某条方便的 progress 曲线来竞争。PRO6000 必须按 task semantic 选择：

1. **Detection-service**：IQ 校准 `SINR -> P_d(P_fa,N,Swerling)`，按 detector draw/expected service 累积；
2. **Fisher-information debt**：跟踪/估计 task 累计 `H^T R^-1 H`，低 SINR 用 missed-detection gate，禁止无限外推 CRB；
3. **Mutual-information debt**：仅用于表征/识别 task，并验证与最终完成指标单调；
4. **Legacy sqrt**：只作回归与 ablation，不作新主结果。

## 共同的停止条件

- M7 源码、raw seed records、checkpoint hash 或 metric provenance 未恢复；
- IQ/detector calibration 不通过；
- actor/scripts/oracle 没有通过同一 action feasibility path；
- causal planner 相对最强冻结脚本的保守 headroom 小于预注册阈值；
- untrained/random/shuffled-observation 与 trained pilot 不可区分；
- 预算或物理参数只有在查看 test seeds 后才能“调出”优势。
